# Cursor 开工说明（dev-swarm cursor-qa 适配）

> 本文件给两个读者：**human**（怎么贴）与 **Cursor**（怎么开工）。第一期唯一的非 CC 适配。

## human：怎么叫醒 Cursor

从需求 `_state/current.md` 复制「下一手」块，贴进 Cursor 会话，附 monorepo 本地路径。固定模板：

```text
【dev-swarm 开工】
仓库：<本仓库根目录>
需求：workspace/{需求名}/
下一手：
  agent: cursor-qa
  action: {从 current.md 抄}
  blockers: {从 current.md 抄，应为空}
先读 skill/protocol/agent-contract.md 对应节点权限行，再干活。
```

## Cursor：开工四步

1. **验归属**：读 `workspace/{需求名}/_state/current.md`，确认 `next.agent == cursor-qa` 且 `next.blockers` 为空——否则停，报告归属
2. **验工作区**（目录隔离 ≠ 工作区隔离——多需求共享同一 git 工作区）：`python3 skill/scripts/check_workspace.py workspace {需求名}`
   - ERROR=他需求脏区（E-dirty）→ **拒开**：本需求默认进 worktree（见 `skill/pipeline/ops/05-开发编码.md`；F05：他需求脏区时第二需求开工的默认路径）或先让其收口；**禁止 reset 清盘**
   - BLOCK=profile 口径不一致或判不定（B-profile）→ 停，报告 human 落 decisions（开好头原则 D004）
3. **读权限**：读 `skill/protocol/agent-contract.md` §2 找到自己的节点行（方案审查 04 / 代码审查 06 / 自动化测试执行 09 / 发布验证与观测 14；data-script 链无 08——reverify 首批由 13 写，你只照常消费该表），**只写允许清单内的文件**
4. **干完写回**：
   - log 追加行署名 `Agent: cursor-qa`，「内容」栏标注 `[实证]`（实跑+trace）或 `[推断]`（代码归纳）
   - 状态跃迁：改 status.md（仅当前状态）+ INDEX **同一次提交**；「已验证」只有你能写；打回= reverify 行「已打回」+ 同次 status 回「待修复」
   - commit 自主进行（workspace/ 数据路径），`Agent: cursor-qa`；push 按 `push_policy`——**local-only（默认）只 commit 不 push**，收尾/备份统一执行（SPEC-提交规约 §1.1）；collaborative 才节点末 push（push 前 `pull --rebase`）

## 发布验证与观测（14，java 链专属）

- **触发**：human 完成某项配置或发布后**通知**你（对话消息）——只验证**被通知的那一项**，不代操作发布平台、不代通知
- **三项验证口径**（详见 `skill/pipeline/ops/14-发布验证与观测.md`）：① 脚本与生产数据（表/字段/类型，对照 `10-发布CheckList/` 发布产物脚本，不只看执行成功）② 插入数据（行数、关键字段与脚本一致）③ 服务发布后（启动日志正常+观察五分钟异常日志）
- **记录**：每项验证当轮回写 `workspace/{需求名}/14-发布验证与观测.md` 记录表（结果只用 通过 / 发现问题，后者同笔指向 BUG-{NNN}）；发现问题立单反馈 human，修复归 cc-dev 修复子节点
- **收口**：全部发布项已通知并验证=human 确认（gate=human）→ 进 11 复盘

## 禁止项（contract 强制）

> 推进门禁（gate）权威源 = **需求 profile 的 `advance_gates`**（`skill/pipeline/{profile}.yaml`，F07/D005：java-business 的 01/02/03=human，toolchain=auto）；仓级 `dev-swarm.yaml` `nodes.stages.*.gate` 兜底——human 卡点是否停等以 profile 为准。

- ❌ 改业务代码仓（发现问题开单/列清单转 cc）
- ❌ 改 Apollo / 环境配置
- ❌ 复验失败自己打补丁
- ❌ 补单测与复验配给同一节点
- ❌ 把代码阅读写成环境通过（代码审查只做代码路径，环境实跑归 09/执行）
- ❌ 待复验列表实例/数据根为空时猜测——停，写阻塞原因等 human 部署（两列写「无」=显式不涉及，可继续）
- ❌ 执行 `git reset --hard`，除非用户当条消息显式给出要保留的 commit（先 commit 再丢弃工作区）
- ❌ 整目录 `git add`（点名 add：只暂存明确文件清单，contract §2 暂存纪律——共享工作区会收走他人未提交写入）
- ❌ 事后 amend/filter-branch/soft reset 补署名（`Agent: cursor-qa` 提交时落笔，SPEC §4；修史仅 human 当条消息显式指令）

## 你消费的唯一开工信号

`workspace/{需求名}/reverify.md`——只认这个表（单号/代码根/commit/数据根/复验动作/期望/实际/实例/状态），不认聊天里的口头描述。实例**空**或数据根**空** → 停，写阻塞原因（不猜 IP）；两列写「无」= 显式不涉及，可继续复验，但你对其合理性有质疑权（质疑=打回）。

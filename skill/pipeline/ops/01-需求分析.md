# 操作卡 01 — 需求分析（java-business，agent: cc-dev）

## 调用子 skill 与参数

`req-analysis`，context 传入：

- 需求标题、原始需求描述
- TAPD ID / workspace_id（如有；TAPD MCP 只读拉取=本阶段允许，contract §2 TAPD 边界①）
- 主项目路径（services.yaml local_path）
- GitNexus 组（current.md/需求信息有则传，无则不传）
- OUTPUT_DIR（显式）：`{MONOREPO}/workspace/{需求名}/`
- 状态目录：`{MONOREPO}/workspace/{需求名}/_state/`

## OUTPUT_DIR 与产物

- 产物：`workspace/{需求名}/01-需求分析.md` + `attachments/`
- 末尾必写 `## 小结`（产出/阻塞/已知缺口/交接 四 bullet——「已知缺口」为防「文档说完成但代码没完成」的核心机制，不可省略）

## 阶段特殊要求

- 附件（设计稿/数据文件）由 req-analysis 自动下载进 attachments/ 并在正文引用
- 状态词写成唯一组合；会反转的口径写进 decisions.md 并点名要改的注释/文档/单测
- **盘点对账（F04/D003-v3）**：01 声称文件数/文件清单时，当轮留对账块——```inventory 围栏，行式：`cmd: <find/ls 命令，绝对路径或仓库根相对路径>`、`当轮输出: <人读留痕>`、`声明: <计数>`；命令白名单=find/ls、以仓库根为 cwd；当轮核对：`python3 skill/scripts/check_inventory.py <01路径>`（04 复核加 `--drift-tolerant`，时点漂移不判失败）

## 门禁自检项（java-business.yaml gates.需求分析）

- [ ] 状态词唯一组合，中间态各有对外文案
- [ ] 会反转的口径已进 decisions.md
- [ ] 依赖环境开关的验收写明测试环境进入方式/谁改/如何恢复

## 衔接（dev-swarm 编排）

上阶段小结机械截取后构造下一阶段 context（模板原文）：

```
【交接依据 — 权威，以此为准】
{上阶段 ## 小结 段落原文}

【输入素材 — 供你设计参考】
上阶段产出文件: {0N-XXX.md 完整路径}
工作流目录: {MONOREPO}/workspace/{需求名}/   ← 正式产物目录根
你需要时自行读取正文作为设计输入。但：
- 交接项（阻塞/产出/交接）以上述"小结"为唯一依据
- 不得从正文中提取新的"阻塞/交接"字段
- 正文中若发现小结遗漏的关键信息，向用户提出，不要自行补接到交接项
```

小结缺失 → 提示补写或人工确认，不自行 LLM 提取（不编造）。

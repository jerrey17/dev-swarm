# 操作卡 10 — 发布CheckList（java-business，agent: cc-dev；gate: human per D004）

## 调用子 skill 与参数

`release-checklist`：基于最终代码状态生成三块式清单。OUTPUT_DIR（显式）：
`{MONOREPO}/workspace/{需求名}/`，产物 `10-发布CheckList.md`。

## 产物（三块式，原文）

- **我要操作的**：有序步骤，依赖顺序标注明确（先改配置还是先发代码、发布顺序、验证点）
- **我要关注的**：灰度开关/回滚开关/监控项/告警阈值/核对项
- **如何回退**：git revert 路径/配置回退值/数据回补方案，逐操作可执行

08/09 阶段回填的配置类问题（bug 修复阶段回填清单）必须纳入「我要关注的」。
toolchain 类需求含 workspace 仓迁移节（F13 契约：新仓地址/迁移方式/push 竞争策略；写权限=human）。

## 发布产物（K5；14 节点验证的对照物）

按本需求实际要发布的内容，把可执行材料落成产物文件于 `10-发布CheckList/` 子目录（文件前缀编号，`01-DDL-*.sql` 式）。类别参考（七类，**参考非强制**）：DDL 建表加列 / 刷数 SQL / 白名单导入 SQL / Apollo 配置清单 / OA 菜单与权限配置 / Saturn 作业与备份 / 回滚预案。

- **没有的类别不强行生成空文件**；有的类别**必须落成产物文件，不得只写在清单正文**
- 三块式正文保留；「如何回退」引用回滚预案产物路径（正文=导航，产物=可执行）
- 产物是 14 发布验证与观测的核对基线（对照脚本核表/字段/类型、按插入脚本核行数与关键字段）

## 门禁自检项（gates.发布CheckList）

- [ ] 三块完整；「我要操作的」步骤顺序依赖标注明确
- [ ] bug 修复阶段回填的配置项已纳入
- [ ] 发布产物：有的类别已落产物文件（非仅正文）；无的类别未强造空文件

## 衔接

发布动作本身 human 执行；**每完成一项配置或发布即通知 cursor 验证该项（见 ops/14）**；全部发布项已通知并验证、human 确认收口后进 11 复盘。

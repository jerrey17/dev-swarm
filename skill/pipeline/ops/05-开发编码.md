## 阶段特殊要求（原文迁移）

**状态表按功能点拆分，禁止按服务聚合**——每功能点独立一行（`✅`/`🔶`/`❌`）；`🔶` 必须在「已知缺口」说明具体缺什么。错误示例：一行「api.xxx ✅ 核心完成」掩盖多项功能。**禁止预标未完成项**。

**阶段结束前代码核查**（写 05 文档之前必做）：

1. 对每个 `✅` 功能点读对应代码文件验证：方法体非空、非骨架 echo、核心逻辑存在
2. 差异如实降级（`✅`→`🔶`/`❌`）
3. 核查结果写入 05「代码核查记录」子章节
4. 不得委托子 Agent（不继承上下文会漏判），Leader 亲自执行

**阶段末自检（可选但推荐）**：调 `doc-design-code-gap-review` 做三方对齐自检——
模式 `REQ_DESIGN_CODE`；`OUTPUT_DIR` **必须显式传入** `{项目根}/workflow/{需求名}/05-代码审查/`（覆盖默认 `.ai_work_space/<日期>/`，确保产物随 Git 归并）；判定门槛 DONE/DONE_WITH_CONCERNS/NEEDS_CONTEXT/BLOCKED（BLOCKED→回 03 修正）。此为 cc 自检；06 cursor 独立审查不可被其替代。

**进度汇报**：每次汇报单列 `🔶` 项缺口与 `❌` 项阻塞，禁止只说「核心完成」。

## workspace 仓并行与 worktree（权威；F02/D003 + F05/D003-v3）

目录隔离 ≠ 工作区隔离：多需求共享同一 git 工作区，`pull --rebase` 拒绝任何未提交改动（SPEC-提交规约 §1.1）。
常态 = 轻量纪律（`push_policy=local-only` 节点末只 commit 各自路径）+ 开工脏区检查（`check_workspace.py` 带需求名）。
**worktree（常态默认路径，F05/D003-v3）**：主工作区存在他需求脏区（E-dirty）时，第二需求开工**默认进 worktree**；单需求（含自身脏区）仍用主工作区；双需求同时收口/收尾备份同走 worktree：

```bash
# 开
git worktree add ../dev-swarm-workspace.wt/{需求名} -b wt/{需求名}
# 收尾：回主工作区合并回 feature-acknowledge（冲突按 SPEC §5 按列分主人原则），再清理
git merge wt/{需求名}            # 或 cherry-pick
git worktree remove ../dev-swarm-workspace.wt/{需求名} && git branch -d wt/{需求名}
```

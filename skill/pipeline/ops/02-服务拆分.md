## 阶段特殊要求

**GitNexus 组置信度匹配**（项目根为多 repo 根时自动识别，原文规则）：

1. `mcp__gitnexus__group_list` 取全部组名
2. 从 TAPD 标题/描述提取业务关键词（服务名/业务域/模块名）
3. 每组调 `group_list(name=组名)` 取 repo 列表
4. 打分：关键词命中组名 +3；命中组内 repo 名 +2；描述模块名命中 repo 名 +1
5. 判定：唯一最高分 ≥3 → 自动选择写入 services.yaml；多个候选（≥2）→ 列 Top3 用户确认；无匹配（<2）→ 列全部组手选；用户跳过 → N/A

**关联项目回填**：衔接时读 02 正文「五、服务改动总览」回填 `services.yaml`（role 枚举：主责/协同/参考），不依赖小结简述。

小结「阻塞」映射：⚠ 未找到仓库 → 先 clone；知识库空白 → 用户确认；否则进技术方案。

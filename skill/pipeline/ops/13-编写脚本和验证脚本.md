# 操作卡 13 — 编写脚本和验证脚本（data-script 链专属，agent: cc-dev；gate: human 拍板后才执行数据变更）

> 适用：刷数/取数需求（services.yaml `kind: data-script`）；不改业务代码、无需发布。前置=04 方案审查放行 + human 拍板（advance_gates 硬卡）。

## OUTPUT_DIR 与产物（四件套，缺一不可）

`workspace/{需求名}/13-脚本/`：

```text
forward.sql    正向脚本（分批+事务边界显式；批大小在文件头声明）
rollback.sql   回滚脚本——与正向等粒度（能撤回 forward 的全部影响）
verify.sql     验证脚本——执行后断言：影响行数=预期、抽样字段值≥3 行、业务校验 SQL
README.md      预览记录：影响范围（表/行数/抽样）、备份表名、执行顺序与批次说明
```

## 数据安全五条（强制顺序，违反任何一条不得交付）

1. **预览**：执行前先跑 SELECT 预览影响范围（行数+抽样≥3 行），记入 README
2. **备份**：UPDATE/DELETE 前建备份表 `_bak_{需求}_{日期}`（或导出文件并在 README 记路径）
3. **回滚**：rollback.sql 与 forward 等粒度；**不可回滚操作（DROP/TRUNCATE/不加 WHERE 的全表改）禁止**——确需时停等 human 特批并落 decisions
4. **事务与限流**：大批量必须分批（批大小声明）、单批单事务；停写窗口/灰度按 03 方案声明执行
5. **验证**：verify.sql 断言全过才算本阶段完成——**verify 跑绿 ≠ 「已验证」**（「已验证」仍只有 09 执行可写）

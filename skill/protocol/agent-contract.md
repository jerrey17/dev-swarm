# agent-contract — 多 agent 协同协议

> dev-swarm 全体 agent（cc-dev / cursor-qa / human）的强制契约。
> 依据：dev-swarm 技术方案总览 V1.7 §6。本文件随 skill/ 迭代，修改须 human 批准（Approved-by: human）。

## 1. 协作定位总则

- **cc 是主要动手方**：需求分析、服务拆分、技术方案、开发编码、单元测试、bug 修复、编写脚本和验证脚本（13，data-script 链）、发布验证与观测/修复（14 子节点）
- **cursor 是审查与测试方**：方案审查（04）、代码审查（06）、Agent自动化测试执行（09）、发布验证与观测（14，java 链）——交叉制衡，禁止自己查自己
- **human 拍板与部署**：口径拍板、部署、Apollo、实例填写、工具迭代批准、退役删除动作
- 互相协作：审查方只提差异/问题清单，修正归动手方

**产物与暂存纪律（V3/D003-v3）**：

- **证据覆盖面（F01）**：检查类证据（typecheck / 单测 / 脚本跑通）必须写明「证据覆盖面：工程=… 目录=… 命令=…（含退出码）」；缺三要素=审查清单指出
- **点名 add（F03）**：只暂存明确文件清单（`git add` 具体路径），禁止整目录 add——共享工作区会收走他人未提交写入（P3 连坐实证）；pre-commit 对 workspace/ 下 ≥2 需求目录混存直接拒绝

**TAPD 边界（V2-R5，三条写死）**：

1. **需求拉取**：01 需求分析允许调 TAPD MCP（只读：story 内容/附件/评论）。
2. **方案推 Wiki**：03 技术方案完成后可选调 tapd-wiki-publish（推送前 human 知会）。
3. **bug 台账↔TAPD**：本地三文件（status/log/INDEX）归**修复方 cc-dev**；TAPD 缺陷状态流转归**复验方 cursor-qa**（human 拍板项除外）。双份记账以本地为准，TAPD 为同步面——修复子节点不猜、不顺手改 TAPD。

## 3. 状态六词与跃迁规则

缺陷状态只用六词：**待确认 / 待修复 / 已修复待验 / 已验证 / 已关闭 / 作废**

- 「待修复 ↔ 已修复待验」区间归**开发 agent**
- 「已修复待验 → 已验证 / 打回」跃迁归**复验 agent**
- 「已验证」只由复验节点写；开发 agent 写已验证 = 违规，协议拒绝
- 打回：reverify 行状态置「已打回」，**同次**把缺陷 status 改回「待修复」（不新增第七个状态词）
- 作废/已关闭：双方可提请，human 拍板

## 4. 台账三文件协议

**BUG-{NNN}/status.md**（单跃迁状态文件——仅当前状态，无追加表格）：

```yaml
---
id: BUG-062
status: 已修复待验            # 六词之一
updated_at: 2026-10-03T11:00:00+08:00
---
```

**BUG-{NNN}/log.md**（append-only 事件流；跃迁史也在此）：

```markdown
| 时间 | agent | 类型 | 内容 | 证据 |
|------|-------|------|------|------|
| 2026-10-03 10:30 | cursor-qa | 立单 | 上传地址多一层前缀，浏览器请求 500 | [实证] Network URL |
| 2026-10-03 11:00 | cc-dev | 跃迁 | 待修复→已修复待验 | — |
| 2026-10-03 11:00 | cc-dev | 修复 | 去除前缀拼接，commit abc1234 | [实证] 单测+复跑 |
```

规则：**只追加不改对方行**；类型枚举=立单/修复/跃迁/复验/部署/复位/备注；「内容」栏实证/推断必须标注；动过 Apollo/测试库写「待复位」行，阶段收尾两侧对账。

**bug/INDEX.md**（衍生索引）：由做这次跃迁的一方改，**与 status.md 同一次提交**。

立单六要素：现象 / 环境 / 复现路径 / 预期 vs 实际 / 影响范围 / 证据。

## 5. 开工信号协议（reverify.md）

| 单号 | 代码根 | commit | 数据根 | 复验动作 | 期望 | 实际 | 实例 | 状态 |
|------|--------|--------|--------|----------|------|------|------|------|
| BUG-062 | /path/atm.win | abc1234 | /data/clone | 浏览器实际上传 URL | URL 无多余前缀 | （复验后填） | 10.0.0.8:8080 | 待复验 |

- 写入者：**修复子节点的 agent**（不写死 cc）；**首批**写入者=提测(08)，data-script 链 08 缺位时由 编写脚本和验证脚本(13) 承接
- 复验节点（cursor-qa）**只消费此列表**；行状态只用：待复验 / 已复验 / 已打回
- **实例为空 → 测试节点停**，在 log 写阻塞原因，不猜 IP；**数据根为空 → 同停**（v2 新增，随加列）
- 「无」= 显式声明不涉及（合法值，不停）：无部署单元类需求实例写「无」，与本条无关的数据根写「无」；复验方对「无」的合理性有质疑权，质疑=打回
- 期望必须字段级（禁「页面正常」）；实际=复验后必填的原始输出摘录
- 新条目由 console 轮询检测并企微通知 human

## 6. 下一手协议（current.md next 字段）

```yaml
next:
  agent: cursor-qa        # cc-dev | cursor-qa | human
  action: 复验 BUG-062     # 一句话动作
  blockers: []            # 非空则不可开工
```

- 字段化，**禁止自由文本**
- 开工校验：`next.agent == 自己` 且 `blockers` 为空，否则拒绝开工
- 跃迁原子性：phase/node/next 三字段同一次提交变更

## 7. 提交规约

见仓根 `SPEC-提交规约.md`（分路径：workspace/ 数据自主提交；工具路径 push 须 `Approved-by: human`；业务仓不主动 push，commit 后汇报 appid+范围+描述）。

## 8. bug 修复四原则

1. **下一层**：复验失败先回答「当前根因层之下还有没有封装层副作用」，读穿公共封装源码再改；**禁止在原补丁上打补丁**（055/062）
2. **待复位**：动过的 Apollo/测试库写「待复位」行，阶段收尾两侧对账
3. **实证/推断**：台账「实际」栏必须标注；推断类开发侧先自己验再改
4. **方案回溯**：根因在方案口径分裂时，修复子节点强制回溯方案原文（引用章节号）、口径定稿落 decisions、方案文档随修复批次修正（054）——**04-方案审查不能代替这次回溯**

## 9. 隔离与会话纪律

- 过渡期与存量 dev-workflow 五维隔离：触发词互斥（本体系触发词=/dev-swarm、swarm 需求、swarm 进度）、`_state/` 路径隔离、数据零共享、代码零依赖、同会话不同时运行两 skill
- 违反任一条 = 干扰存量，立即停止并报告 human
